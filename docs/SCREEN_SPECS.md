# Screen Specifications — Expense Tracker v1.0

**Source of truth:** [PRODUCT.md](PRODUCT.md) for accounting and scope; [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) for visuals. Screen IDs below are stable references for tasks/tests. Every screen operates offline. Default reporting currency is INR.

## Shared interaction conventions
- Save buttons activate only for valid input; when invalid, show inline error, preserve input and move focus to first invalid field. Never silently change numeric amounts.
- Default keyboard for amounts: decimal numeric; visible ₹ prefix outside editable number; max 2 fraction digits; accept pasted `1000.50` and optionally `1,000.50`; reject negative, symbols besides separators and excess precision. Convert to paise without floats. `Done` hides keyboard; `Next` advances through optional fields.
- Tapping outside input closes keyboard only where it doesn't cause data loss. Date picker defaults to current local date. Form Back with changes offers **Discard / Keep editing**; closing a pristine form simply goes back.
- On Save, use atomic local persistence; disable duplicate submission while pending; pop screen only on successful commit. Provide a persistent result screen/list state plus short confirmation, not snackbar-only success.
- Loading: use subtle skeleton/progress only for actual Room read/compute delay, no fictitious network loading. Error: accessible inline error + Retry on read failures; on persistence failure remain on form with Retry. Empty states include one primary action.
- All tap targets ≥48 × 48 dp; TalkBack describes action, amount, group, date and status in a meaningful order. Announce totals and result counts on change. Support 200% text without clipping or fixed-height truncation. Never encode owes/owed only by red/green.
- Row tap opens detail; overflow actions have labels. Destructive actions always confirmed or safely undoable. Use edge-to-edge, correct system-bar insets and IME padding.

## Navigation and route map
```text
FirstLaunch (ONB-01) -> Today (HOM-01)
App shell: Today (HOM-01) | Activity (ACT-01) | Groups (GRP-01) | Insights (INS-01)
Today/Activity -> Add personal (EXP-01) -> save -> previous
Today/Activity -> Personal detail (EXP-02) -> Edit (EXP-01) / Delete confirm (COM-01)
Groups -> Create group (GRP-02) -> Group detail (GRP-03)
Group detail -> Add member (GRP-04) | Add shared (SHR-01) | Balances (BAL-01)
Group detail/Activity -> Shared detail (SHR-02) -> Edit (SHR-01) / Delete confirm (COM-01)
Balances -> Record settlement (SET-01)
Group detail/Activity -> Settlement detail (SET-02) -> Edit (SET-01) / Delete confirm (COM-01)
Today top menu -> Settings (CFG-01)
```
Activity opens group-scoped shared detail, even if the group is archived. Back-navigation restores filters, scroll position and month selection. Creation success navigates to created group; nested edits return to detail, unless that detail was deleted.

## ONB-01 — Welcome / local profile
**Goal:** Enter app without accounts. **Hierarchy:** small illustrative branded header, “Track spending, together or solo” title, brief privacy copy, display-name field prefilled “Me”, primary `Start tracking`, footer “Saved only on this device; uninstall or clearing data may delete it.” **Validation:** trimmed name 1–40 characters; blank falls back to “Me” when user explicitly chooses Skip. **Interactions:** Start/Skip record profile and complete onboarding in local persistence, route Today with back stack cleared. **States:** immediate content; persistence error retains form with Retry; success shows Today empty. **A11y:** footer readable, no essential graphic information.

## HOM-01 — Today
**Goal:** Add fast and see personal spending. **Hierarchy:** top app bar “Today” + Settings menu; month label/previous-next controls; large **Personal spending this month** amount; small category overview or top category; `Add expense` prominent FAB; recent **personal** transaction rows (date, title, category, amount); secondary “Shared groups” link. **Validation:** none. **Interactions:** Add launches EXP-01; tap row detail; View all Activity; month navigation changes personal summary and recent list. **States:** empty CTA “Add your first expense”; skeleton for initial local read if needed; read error Retry; save success updates month and list immediately. **A11y:** announce “Personal spending,” currency, period; list grouped by date; no ambiguous plus/minus sign.

## EXP-01 — Personal expense form (create/edit)
**Goal:** Store payment with minimum effort. **Hierarchy:** screen title Add expense/Edit expense; large amount field at top auto-focused on create; next Title (optional, default derived category or “Expense”); Category picker chips (default Other, recent selection used only if user chooses a preference later); Date selector (today); expandable Notes (max 300 characters); sticky primary Save. **Required:** amount >0, ≤₹10,00,00,000.00, INR two decimals; category fixed enum; date within 2000–2100. **Optional:** title 1–80 trimmed characters if supplied; note max 300. **Interactions:** numeric IME appears on create, Save available as soon as valid amount; date picker, category select; edit loads values without auto-opening keyboard and preserves original ID. **States:** invalid format and over-limit helper text; if read error on edit, retry instead of blank form; write failure preserves fields; success returns updated list/detail. **A11y:** amount hint “Amount in rupees”; read-only currency prefix; focus goes to amount error; valid amount accessible without depending on stylized digits. **Performance target:** Add -> digits -> Save, no other required gestures.

## EXP-02 — Personal detail
**Goal:** Confirm a recorded purchase and manage it. **Hierarchy:** amount as hero, title/category/date, note if present, created/edited metadata, Edit and overflow Delete. **Interactions:** edit EXP-01; delete COM-01; back retains originating list state. **States:** if record no longer exists, show “Expense unavailable” with Back; details otherwise local/immediate. **A11y:** semantic labels for metadata and controls.

## ACT-01 — Activity/history
**Goal:** Find any event across scopes without conflating types. **Hierarchy:** top bar Activity; text search; scope selector `All / Personal / Group name`; month picker; Type `All / Expenses / Settlements` (settlements shown only for group/all); category chips for expense results; total result count; date-grouped lazy list of personal, shared and settlement entries with explicit type/scope badges. **Rules:** `All` is a mixed feed **without a misleading combined total**; group filters affect only that group; category filter removes settlements; text search on title, note, member/group names; case-insensitive, trimmed. **Interactions:** filter changes update list; tap opens appropriate detail; clear all resets month=all months, scope=All, type=All, category=All, search empty; back preserves filters. **States:** zero-all-data -> CTA Add; no matches -> Clear filters; search debounce optional but results must match final query; read failure Retry; loading indicator only on expensive queries. **A11y:** selection states announced and rows say `Personal expense` or `Group settlement`, amount, date.

## INS-01 — Monthly Insights
**Goal:** Understand personal spend by month. **Hierarchy:** top bar Insights; period selector with month/year; hero “Personal spending” total; category distribution as textual rows with amounts and percentages plus optional compact bars; count of expenses; bottom recent personal entries. **Rules:** personal only; category percentages derived from integer paise, formatted to whole percent and may visually sum 99%/101% due to presentation rounding; amounts always authoritative. No income, net balance or group purchases. **Interactions:** previous/next months (future months allowed), tap category filters ACT-01 to same period. **States:** no personal entries -> informative empty with Add; local query error Retry; numbers recompute after create/edit/delete. **A11y:** accessible category list is sufficient without chart; announce month and total.

## GRP-01 — Groups list
**Goal:** Choose a local shared ledger. **Hierarchy:** title Groups, `New group` button, list of groups with name, members count and user's signed net (`You owe`, `You're owed`, `Settled`) and “On this device” label at initial empty state. **Interactions:** open detail; create; archived groups in a labeled section (readable, no new shared expenses unless restored; restore deferred to P1, so archive reversible only via future product version—warn before archiving). **States:** no groups -> illustration/text+New group; data error Retry. **A11y:** amounts include direction verbally.

## GRP-02 — New group
**Goal:** Create a household ledger. **Hierarchy:** title, group name field, members editor: local owner “Me” always included and not removable; add member name one at a time; local-storage explanation; `Create group`. **Validation:** name trimmed 1–60 chars; at least 2 members; member names trimmed 1–40 chars, unique case-insensitively per group; upper limit 30 members; no blank entries. **Interactions:** Add member inline; remove unsaved member chip; Create transactionally persists group/members; success navigates group detail. **States:** field errors inline; save failure retains state; no duplicate groups on double tap. **A11y:** announce member count and remove chip labels.

## GRP-03 — Group detail
**Goal:** Review activity and reach actions. **Hierarchy:** app bar name + overflow Archive (and Delete only if no history); section “Your net position” with status; CTA `Add shared expense`; CTA `Balances & settle`; members count/chips; group spending this month (distinct from balances); dated group event list (shared expenses and settlements), newest first. **Interactions:** open BAL-01, SHR-01, group event detail; Add member GRP-04; archive confirm; change month in local group spending view. **States:** no activity -> “Add your first shared expense”; no owed balances -> Settled; archived mode disables creating/editing new events except viewing existing records (intentional v1 restriction); load error Retry. **A11y:** voice distinguishes month spending from net owed.

## GRP-04 — Add group member
**Goal:** Add a local member without inviting them. **Hierarchy:** small form/bottom sheet with member name, “This person will not be notified”, Add. **Validation:** same name rules as GRP-02, max 30 group members; inactive names not reused unless group-wide uniqueness maintained. **Interactions:** Save inserts member; old expense shares unchanged; new member selected by default for future equal split; Cancel. **States:** field conflict, write failure, success group member list update. **A11y:** sheet has meaningful title; focus trapped appropriately.

## SHR-01 — Shared expense form (create/edit)
**Goal:** Record group payment and exact beneficiary shares. **Hierarchy:** `Add shared expense` / `Edit shared expense`; amount; title; category; date; `Paid by` member selector (single); `Split among` selectable group member chips/rows (all active selected on create); segmented `Equally / Exact amounts`; live share rows showing each amount; fixed summary `Total ₹X / Assigned ₹Y / Remaining ₹Z`; optional note; sticky Save. **Validation:** amount and metadata like EXP-01; active payer; ≥1 included beneficiary; all shares nonnegative paise and assigned sum exactly equals amount; no invalid/inactive member added as a new beneficiary; on edit existing historical inactive members retain shares. **Interactions:** amount edit recalculates equal split immediately; toggling to Exact initializes shares from current equal allocation; changing amount in Exact retains entered shares and shows remaining discrepancy, does not silently rescale; changing selection in Exact preserves remaining values but requires manual reconciliation; screen reads derived net preview. Editing past group transactions allowed while group active and shows recalculated group results. **States:** empty group member precondition blocks entry; invalid split disables Save with inline Remaining; stale/deleted payer error with retry/reload; persistence failure retains exact form; success returns group detail. **A11y:** each member row says name, included/not included, share in rupees; summarize sum mismatch in text; keyboard IME above sticky footer. **Important:** when edited, group ID and transaction ID are unchanged.

## SHR-02 — Shared expense detail
**Goal:** Audit who paid and who participated. **Hierarchy:** amount/title/date; “Paid by Name”; split member list with exact shares; note; small notice “Recorded locally”; Edit/Delete. **Interactions:** edit; deletion confirmation warns balances and settlements may change; Back. **States:** missing item error; if group archived, read-only. **A11y:** read payer and each share as independent labeled values.

## BAL-01 — Balances
**Goal:** Understand outstanding net positions and record offline settlement. **Hierarchy:** group title, “Based on all group expenses and recorded settlements”; signed balances for all members, owner highlight; `Suggested settlements` rows like `A pays B ₹42.50`; CTA `Record settlement`; compact explanation `Recording doesn't send money`. **Rules:** suggestions deterministic and reconcile all member net values; ties broken by stable member ID, not list order. If all net positions zero, state “Everyone is settled.” **Interactions:** selecting suggestion prefills SET-01; manual new settlement chooses only currently suggested pairs; open settlement history in Group detail. **States:** no expenses -> friendly empty; inconsistent historical settlement after edits -> “Review balances” informational warning but never fake a payment; read error Retry. **A11y:** use full “pays” phrases, no arrow-only or color-only meaning.

## SET-01 — Record/edit settlement
**Goal:** Record a real-world payment already made. **Hierarchy:** heading `Record settlement`, explainer “This does not transfer money”, From member, To member, amount, date, optional note, primary `Record settlement`. **Validation:** distinct participants, both valid members in group; >0 and within suggestion for new record; date 2000–2100; optional note 300 chars. On editing historical settlement, validate amount and distinct members; do **not** reject saved legacy edits solely because earlier expense edits altered suggestions—display advisory and recomputed preview. **Interactions:** choose suggested pair prepopulates From/To/max amount; amount numeric IME, default suggestion amount; Save atomic; after success return Balances. **States:** all settled -> disable action/return informative empty; suggestion changed before save -> inline “Balance changed; review amount”; failure leaves form intact. **A11y:** From/To explicitly “Person paying” and “Person receiving”.

## SET-02 — Settlement detail
**Goal:** Verify an offline transfer record. **Hierarchy:** amount, “From paid To”, date/note, “This is a record, not a transfer”, Edit and Delete. **Interactions:** edit SET-01, delete COM-01; archived group read-only. **States:** missing record error; success updates group net after modify. **A11y:** payer/receiver spoken in correct direction.

## CFG-01 — Settings
**Goal:** Manage local preferences and understand risk. **Hierarchy:** local display name, theme selector System/Light/Dark, “Your data” explanation, optional app version, destructive `Delete all data`. **Validation:** name 1–40 chars; changes to name do not modify historical group-member identity IDs. **Interactions:** update settings immediately; Delete all -> COM-01 with explicit permanent-loss copy and confirmation. **States:** update failure with Retry; success persistent selection; screen readable in both themes. **A11y:** appropriate settings switch and radio semantics.

## COM-01 — Destructive confirmation / Undo
**Goal:** Prevent accidental loss. **Hierarchy:** specific title (`Delete expense?`, `Delete settlement?`, `Archive group?`, `Delete all data?`), impact description, Cancel and explicit destructive button. **Rules:** for shared record, state balances will be recomputed; for group archive explain read-only/no unarchive in v1; for delete-all no Undo. For individual delete, use snackbar Undo if full restoration snapshot is supported; never promise Undo if not implemented. **States:** deletion failure with recovery; successful delete visibly removes row and updates totals. **A11y:** focus title and give buttons unambiguous labels.

## Cross-screen acceptance baseline
For each route: state survives rotation as reasonably possible; no crash with IME open; back behavior coherent; dark/light legibility; TalkBack screen heading and actionable controls; no clipped money at 200% font; process death retains committed data; no content visually obscured by system bars or keyboard. Specific scenario IDs live in [ACCEPTANCE_CRITERIA.md](ACCEPTANCE_CRITERIA.md).
